# Kimi K3 65,536-token real-data A/B acceptance

## Status

Conditional acceptance: the project, real-data pipelines, K3 integration, and A/B evaluator work end-to-end. The free NVIDIA-hosted K3 endpoint has high and variable tail latency, so it is not yet suitable for a production latency promise.

## Effective runtime configuration

- Model: `moonshotai/kimi-k3`
- Output ceiling: `65536` tokens (the accepted NVIDIA K3 maximum)
- Reasoning: `max`; temperature: `1.0`; streaming: enabled
- Serial spacing: 30 seconds
- Bounded acceptance batches: 300 seconds per attempt and two attempts per architecture/case (`NVIDIA_REQUEST_TIMEOUT_SECONDS=300`, `NVIDIA_RETRIES=1`)

`max_tokens` is an output ceiling, not a requested answer length. The same model, prompt, seed, and reasoning setting were used for the paired A/B calls. The observed variability is request completion latency at the hosted endpoint, not an invalid token setting.

## Real-data basis

- Normalized public legal cases: 140,292 total — LegalBench 90,894, CaseHOLD 42,509, and LegalBench-RAG 6,889. See `data/processed/benchmark/manifest.json`.
- Official eCFR authority corpus: 5,683 records. See `data/processed/authority/manifest.json`.
- Local DGX Spark embedding index: 58,604 vectors, 2,048 dimensions, generated with `nvidia/Nemotron-3-Embed-1B-BF16`. See `data/processed/embedding-index/manifest.json`.

## Decision

The 65,536-token configuration is valid and produces successful, cited legal answers on two real public sources. Keep it as the quality-acceptance default. For operational batch work, retain the explicit two-attempt/300-second envelope and report provider timeouts separately from answer-quality scores. Do not infer a full-corpus online A/B score from this sample: 140,292 cases require 280,584 serial paired provider requests, and the 30-second spacing alone exceeds 97 days.
